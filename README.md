# MT — Master Trade

`MT.mq5` is a MetaTrader 5 Expert Advisor with a market panel, independent timeframe readings, informational trade plans, an observed-market diary and optional broker auto trading. **Auto Trading defaults to false**; when enabled, it can send real orders. Copy `MT.mq5` **and all `MT_*.mqh` files** into the same `MQL5/Experts` folder, compile in MetaEditor, and attach it to a supported chart. Native compilation, MT5/broker integration and out-of-sample target performance are not yet verified.

## Panel

Panel rendering is isolated in `MT_Panel.mqh`; copy it into the Experts folder with the EA and the other includes. The panel uses a dark slate background and Consolas text. The top header groups the market state, symbol, trade totals, timer status and server clock; Bid/Ask appear beside Auto Execution. Full timer details and abnormal market detail appear beneath the header when needed. The settings box groups Auto Trading, SL Placement, Bypass Risk and Minimum Lot on the first row, followed by TP percentages, Trend to Follow and each lane’s Allow Against Trend. Groups wrap on tight charts. Diary Details is controlled by its input and is indicated by the separate window rather than a settings badge. These are input settings, not a guarantee that an order is permitted; the against-trend switches are not separate lane-enable switches.

The header carries the symbol-wide trade record on one line, after the OPEN/close chip: `T S n W n L n   |   A S n W n L n` — T for today, A for all time, across M5/M15/M30 together. Break-even records remain in the diary but are omitted from this compact header. Per-timeframe counts are not in the main panel; they are in the diary window.

Under the settings the panel is two columns. On the left, `MARKET READINGS` (an aligned M5/M15/M30 table of TF, GT, CT, ST, RG, PT, SC and SG) sits directly above `TRADING PLANS`, where M5/M15/M30 are stacked vertically and each row is exactly as wide as the readings table — a NONE lane is a single line, a priced plan adds Entry/Lot/SL/TP. On the right, `AUTO EXECUTION` starts level with the readings and stacks the three lanes' broker status. Columns are only as wide as their own header and values, so the eight values sit compactly together with SG at the right of SC; the readings box ends at its last column instead of stretching across the panel. Each stacked plan row places Entry, Lot, SL and TP in four shared columns, with volume and order style on its header line; signed account-currency estimates appear beside SL and TP, wrapping under them only if the row runs out of width. A NONE plan collapses to one line. Auto-execution rows place broker Entry and Lot beside the OPEN/LIMIT badge, then wrap remaining exit and warning details as needed. Three separate cards show the frozen trading plans; the auto-execution section shows each lane's broker-confirmed order/position or current status; and the header line shows the symbol-wide Today and All counts. `Show diary details` opens the details in a separate window to the right of the panel instead of adding rows to the statistics box. Plans are not broker orders: the auto section displays the broker's actual levels, including a retained SL when placement is switched off. Unavailable readings or diary data remain visible rather than becoming zeroes. Auto-status tooltips apply to every wrapped line. TP distance is in price units, from the current BUY Bid or SELL Ask to the displayed plan or broker TP; negative means the quote has passed that level. It shows `--` if the target or a fresh quote is unavailable. Beside the broker TP distance in each active Auto Execution row, the current entry-side quote is Ask for BUY or Bid for SELL, for both OPEN and LIMIT. The quote uses the broker trade direction, not the plan direction; the exit-side TP distance calculation is unchanged. Pending orders are not fills.

The EA measures text using MT5 font metrics and expands the panel to fit the displayed content; a conservative DPI-based estimate is used if measurement fails. Long plan, status, error and detail messages wrap without truncation. Because the chart objects are not scrollable and the header and table expand for their contents, a narrow chart or unusually long broker messages may require enlarging the chart or reducing display scaling. Exact colors, spacing and font rendering depend on the terminal and display; the redesign is not yet visually verified in MT5.

- M5, M15 and M30: the header shows the broker's symbol, its best-effort asset class and market state. While open it shows server time in the header and the three timeframe lanes below the header and settings, with no clock-estimation guidance. When the broker session is closed, the display collapses to its header and an Automate-style `MARKET CLOSED - next open ... server (in ...)` notice. This only hides the panel sections; the EA continues its normal timer, diary and broker-management processing.
- Other timeframes: the header identifies the symbol and timeframe and the two-line panel shows SimpleEA's `Incompatible chart. Switch to M5/M15/M30.` notice.
- The weekly broker trade-session table is refreshed every five minutes. Sessions may cross midnight. If it is unavailable, a fresh quote can indicate an open market; without a fresh quote the state is unknown and `Open at --` is shown rather than an invented opening time. Disconnection, broker-disabled symbols, and stale quotes are distinguished from a scheduled close.

The next opening is a **regular weekly schedule**, not a guarantee: holidays, broker halts, and changed schedules can invalidate it. `00:00–00:00` is treated as a 24-hour session. Classification uses broker metadata and name heuristics and can be wrong; it does not affect trading.

## Phase 2 readings

Each lane is calculated independently for the chart symbol on the **closed bars** of M5, M15 or M30:

- **GT**: Automate's 30-bar regression slope normalized by the median absolute change of 20 bars; UP/DOWN outside ±0.20, otherwise FLAT.
- **CT**: SimpleEA's adaptive Precision Trend filter sign. Its adaptive short cycle is 14–36 (24 when there are too few crossings); the long period is approximately 6.25 times the short, clamped to 90–225. CT is FLAT at exactly zero.
- **ST**: matching directions give UP or DOWN, two FLATs give FLAT, opposed directions give CONFLICT, and one FLAT with a direction gives MIXED. An unavailable component gives WAIT.
- **RG**: SimpleEA's Hurst estimator on that lane's own data, never a borrowed timeframe. It uses 1,536/512/256 bars for M5/M15/M30, plus the preceding close. Above 0.55 is STEADY, below 0.45 CHOPPY, otherwise MIXED. Invalid data or insufficient history gives WAIT, not a substituted 0.5.
- **SG**: the lane's own signal, identical to its TRADING PLANS card: `BUY`, `SELL`, `NONE` or `WAIT`, and `--` when the plan line cannot be read. It is shown to the right of SC so the readings row and the plan cards cannot disagree.
- **SC**: SimpleEA's three votes: CT direction, its ATR-deadbanded rate of change, and 20-bar net movement with confirmed swing checks and an ATR deadband. It ranges from -3/3 to +3/3. GT, ST, RG and PT do not change the score.

**PT** estimates the remaining life of the selected label: M5 CT, M15 ST and M30 GT. **%L** beside SC independently estimates the share of the exact signed score's estimated life remaining. Each uses the median remaining length of at least 20 fully observed past runs of the same label that reached the current age, including zero remaining. A run beginning before the replay window is not counted. Historical score and adaptive periods are reconstructed causally, without training or waiting for new trades. Estimates can be inaccurate or biased by changes in market conditions or the available historical window.

The countdown basis is held when a state starts or the EA attaches mid-state. A positive life fraction that rounds below one percent is shown as `<1%L`, never as an expired zero. Each subsequent closed bar reduces the remaining count. PT shows `~0b` at its estimate and `0b+` afterward; score life shows `~0%L` and then `past est.`. Each first label change resets the respective countdown, including `+3` to `+2`. Terminal global variables preserve a valid basis across restarts where possible; MT verifies the observed label and age across the intervening bars before restoring it. `--`/`--%L` means that duration is unavailable, not zero. **Neither PT nor %L is a trade-success probability or a guarantee of a change.**

MT requests closed history directly from the terminal, retries synchronization and progressively increases the request when estimates lack samples, up to the **terminal's configured maximum bars per timeframe** (excluding the forming bar). The broker's history, synchronization, terminal settings, invalid data and available memory can limit what is available. If a deeper `CopyRates` request fails, the EA retries the deeper request and can retain independently supported readings from a smaller available range; it never substitutes a regime value. With short history, already supported GT or RG may display while CT/SC still show WAIT. The filter uses a 700-bar warm-up and the finite historical replay can differ slightly from SimpleEA's live rolling pull because recursive filter initialization is not identical. Large history requests and calculations can take time, memory and CPU and may briefly block MT5; data are refreshed on new bars and incomplete history is retried. Phase 2 itself does not place orders; Phase 3 adds the inputs and informational planning described below.

## Server clock

MT5 has one trade-server time for the account, not a separate clock per symbol. In `OnTick`, `TimeCurrent()` is the server-stamped time of the chart symbol's handled quote. Outside `OnTick`, it is the most recent quote time for **any** Market Watch symbol. The panel anchors to new broker timestamps and advances between them using a monotonic counter. This avoids the previous reliance on `TimeTradeServer()`, which MetaTrader calculates from the PC's clock settings. After startup and before a new quote is observed, `TimeTradeServer()` is the only running estimate available. In Strategy Tester, simulated `TimeCurrent()` is used instead of real elapsed time.

A timestamp in a quote has second precision and may be delayed in transit; extrapolation between quotes and over long closures can drift, and a server clock or timezone change can occur without a new quote. **Perfect synchronization cannot be guaranteed by MT5's APIs.** The clock is estimated between quotes. Compare it with Market Watch's server time on a live connection, and check the PC clock if the panel starts before any fresh quote.

## Phase 3 — informational plans and diary

The panel groups the market header (symbol, state, symbol-wide trade totals, clock) and settings above the Phase 2 lanes, then shows the readings table over the three stacked plan rows on the left and auto execution on the right. `Show diary details` opens a separate diary window beside the panel (see below); it does not add rows to the main panel and can cause its width to adjust on a narrow chart. Each plan row contains BUY/SELL/NONE, market or limit entry, lot, SL and TP prices and estimated SL/TP amounts in account currency. Plan amounts are gross `OrderCalcProfit` estimates; a price outcome is not an executed trade. The box still resizes for all rows and label segments.

Inputs: `Trend to follow M5/M15/M30` are four-choice inputs (Auto/CT/GT/ST), default Auto; `Allow against trend M5/M15/M30` default false. `Bypass risk`, `Minimum lot use`, and `Show diary details` default false. Normal sizing targets 0.5% of equity per plan, using the entry/SL loss estimated by `OrderCalcProfit`; broker min/max/step apply and below-minimum lots become the broker minimum. Minimum lot use forces that minimum. Bypass uses SimpleEA's balance ladder (0.01 lot per 1,000 account-currency balance units, 1.5 times at absolute score 3). It is not normalized across currencies. These Phase 3 inputs do not enable trading; Phase 4 adds the separate Auto Trading input.

A score of ±3 uses a post-close Ask/Bid market reference when volume is confirmed or unavailable, but a limit when volume is weak; ±2 always uses a limit. Limits use a confirmed swing or a fallback derived from the median recent directional bar move. For each lane, tick volume on its latest closed bar is compared with half the average of up to 20 positive-volume bars immediately before it (at least 10 are needed). If insufficient volume history is available, the ±3 market choice is retained, as in SimpleEA. The plan row shows `Volume: OK`, `LOW`, or `--` for ±3; this does not change BUY/SELL. SL uses a confirmed opposite swing with spread/tick protection, or a recent-move fallback. For TP, MT reconstructs completed same-signed-score and same-entry-style historical bar analogues, measures favorable movement before the stop over 4/6/8 bars for M5/M15/M30, and uses the selected favorable-movement percentile relative to stop risk when at least 20 analogues exist. On Bid-based charts, a limit touch is assessed using bar-level spread proxies; stop wins ambiguous bars, and the entry bar contributes no favorable extreme. On Last-based charts, or when the chart price type is unavailable, Bid-specific replay is disabled; recent-move fallback and chart-bar structure are used as a clearly labelled Last/unknown price proxy. With insufficient analogues or a zero selected percentile it also uses a recent-move fallback (one tick if no positive directional bar movement is available). TP is capped by an opposing pivot as described below, where compatible with broker-distance constraints. These are initial design choices, not optimized or validated claims. Historical replay is not the diary, and does not use future bars at each historical decision. Entry and plan geometry can be unavailable if required quotes, history or contract data are unavailable; BUY/SELL remains visible.

### TP percentage per timeframe

The three inputs `TP% for M5 (lower = closer)`, `TP% for M15 (lower = closer)` and `TP% for M30 (lower = closer)` are independently adjustable integers from 1 to 100 and default to 81, 83 and 85 respectively. They are active without an on/off switch. Each selects the nearest-rank percentile of the same historical favorable-excursion samples; 85 is not an 85% hit probability, a percentage of the current TP, or a guaranteed best setting. Lower percentiles generally select closer targets, and higher percentiles farther targets; the three values appear in the existing header. An out-of-range input is shown as `INVALID` and that lane uses the original upper-median and nearest-swing logic until the input is corrected; other lanes continue normally.

M5 retains the nearest opposing pivot cap. M15 and M30 use the second distinct opposing pivot by price distance when available; one pivot uses that pivot, and no pivot retains the existing no-pivot behavior. The same 20-sample threshold, zero-target/recent-move fallback, stop-first replay, broker-distance/tick rules and other plan rules remain. The cap, broker floor or fallback can make different percentages produce the same TP. This is experimental and needs independent real-tick/demo comparison. Because the former switch was removed, setting 50 is not an exact restoration of the former logic: nearest-rank 50 differs from the original upper median for even samples, and M15/M30 retain the second-pivot cap.

The defaults apply to fresh/reset inputs; existing chart settings or loaded presets may retain their saved values, so check the Inputs tab after upgrading. Changing any input reinitializes the EA and rebuilds snapshots on subsequent observed quotes. It does not alter an already-open position's broker-side SL/TP. Existing pending orders remain subject to the usual replan, modification, cancellation and broker-confirmation rules. The broker diary records strategy `30006` for the new percentile configuration (`30004` for an invalid lane fallback); existing `30005` records refer to the prior fixed-70 wider mode. New broker-diary requests store the chosen percentage; older records do not. The diary does not store the full later pending-order modification history. Legacy active quote observations can become UNKNOWN on reinitialization.

Each timeframe captures its own first valid quote observed by the EA on a tick after its latest bar closes. Closed-bar structure plus that frozen Bid/Ask (including its spread) produces a snapshot of entry, SL, TP, lot and estimated amounts; panel refreshes and other timeframes' bar closes do not reprice it. This is not a pure OHLC-only plan: market BUY references the captured Ask and SELL the captured Bid, and limit geometry also uses the quote and spread. If attached/restarted mid-bar, after a gap, or if MT5 coalesces ticks, the first quote observed by the EA may not be the broker's actual first quote after the close. A snapshot is rebuilt after reinitialization, not persisted. If history arrives late, the same captured quote is used; if no valid post-close tick is observed, no priced plan is invented. Once priced, a plan with unavailable sizing/amounts stays unavailable until the next lane bar or reinitialization. If retried historical readings change the signal or market/limit type within a bar, an incompatible frozen plan is held rather than silently repriced.

The separate legacy observation diary still records broker quote touches, not fills or realized profit; its values are not displayed as trade results or combined with the new ledger. It counts one idea when a lane enters a new directional signal, rather than on every tick; the same direction is not re-counted until it changes or becomes NONE. If a plan or tick snapshot is unavailable, it records `AWAIT DATA` and can start that same idea later using the then-current frozen plan and real observed quotes while its direction remains current. The frozen market entry is a reference; if observation starts later, its actual starting quote is recorded separately. A market observation waits if its start quote has already passed an exit; the start tick is checked for exits and limit touches. Original signal context and time and later plan context and time are preserved separately; no earlier touch is inferred. Once a plan starts, entry, SL and TP are frozen. Awaiting/pending/open/expired/unknown are not wins or losses. Awaiting and untouched pending observations expire if their lane changes direction or becomes NONE; open observations continue to their original TP/SL. Signals count on their broker-server signal day, wins/losses on their resolution day, and all-time begins with the local diary. The live file is in MT5 Common Files keyed by account, server and symbol; tester files are isolated. It uses a single-writer lock and versioned snapshot. Existing version-3 and version-4 diary records migrate to version 5; version-3 bar-price provenance remains unknown. A second instance cannot record to the same diary. `CopyTicksRange` requests intermediate bid/ask ticks; failure, disconnection, or a mismatch between the tick-history endpoint and quote snapshot makes affected active outcomes unknown. Open/pending observations become unknown on restart because continuous coverage is not certified. MT5 may supply incomplete tick history even without an identifiable error, so the diary is not a broker execution ledger. Hiding details does not stop recording. Changing an MT5 input reinitializes the EA, so already active observations become unknown rather than claiming continuous coverage.

These test actual source through C++ stubs, not MetaEditor or a broker. Test on a demo terminal: compile all files; inspect plan prices, tick size, stops and account-currency amounts; check three timeframe inputs and countertrend switches; compare recorded touch order with tick history; test restart, connection loss, two charts, file corruption and broker-day rollover. Target quality needs independent out-of-sample tick data with spread, non-fill and cost assumptions before relying on it.


### Broker-confirmed trade diary

The main diary rows count actual MT auto orders for the current account, server, symbol and lane, starting with this upgrade; older orders are not silently backfilled. `S` counts a broker-confirmed accepted order, including a later unfilled cancellation, not every signal or an `OrderSend` return. `W`, `L` and `BE` count fully reconciled closed positions with respectively positive, negative and exactly zero net in account currency. Net sums the profit, commission, swap and fee on the linked position's entry/exit deals; separately posted broker charges are not necessarily attributable and are not included. These definitions are not SimpleEA's ±0.05R scratch band. Today uses server day: S is assigned to the request quote's day, and results to the last exit deal's day. All-time starts with this local ledger. Partial, open, unconfirmed and unsupported outcomes are excluded from W/L/BE. The optional details show pending/open/review/unfilled counts, the latest record and its net, per-lane Today/All and analysis, plus any ledger warning such as an unavailable CSV export.

### Separate diary-details window

`Show diary details` draws a second chart window (`MTD_` objects) instead of extending the panel. It sits to the right of the main panel at the panel's own top edge, uses the same slate/Consolas style, and is opened and closed only by that input and by chart support:

- **Per-timeframe history.** Each lane shows Today/All S/W/L/BE, pending/open/review/unfilled, its latest request and net, lifetime closed totals, win rate, net and attributed costs, score 2/3 versus 3/3, BUY versus SELL, market versus limit, and the latest 30 reconciled closes with final broker exit reasons. The latest request also shows its frozen score, regime, spread, SL-placement input and TP-percent input when recorded.
- **Interpretation.** The win-rate denominator includes all fully reconciled closes, including exactly-zero BE. Costs sum linked deal commission, swap and fee; net includes linked deal profit and these costs. A final TP/SL reason describes the last exit deal, not proof of the whole price path. Recent trades are ordered by final broker exit time. Pending, open, unfilled, rejected and REVIEW records are not W/L results. Small samples are descriptive only; the panel does not recommend or change settings.
- **Missing data.** A zero-trade win rate and net are `--`, not an invented zero. Legacy requests have `--` for the new input snapshots. MT has one TP, and does not claim SimpleEA's TP1/TP2/TP3, peak, MFE/MAE, normalized net R or health verdicts without the required data. Full recorded request and broker-deal context remains in the CSV.
- **Layout.** Details wrap to the available width and are paginated when they exceed the chart height. Use the previous/next arrow buttons to view every row. When the chart is too narrow for a readable side column, details overlay the chart; switching the input off removes the overlay.
- **Lifecycle.** The window is removed when the input is turned off or the chart is unsupported (M5/M15/M30 is required, as for the panel). When the broker session closes, the window moves under the collapsed header and continues refreshing; reopening returns it to the right where space permits. The window is display-only and never changes recording or trading.

A separate version-2 binary snapshot named from the account/server/symbol key plus `_trades.bin` and a `.csv` export are kept in MT5 Common Files (tester storage is separate), under a single-writer lock. CSV state codes are 0 intent, 1 broker order, 2 open, 3 closed, 4 unfilled, 5 rejected, 6 review; lanes 0/1/2 mean M5/M15/M30. Version-1 ledgers migrate on load; their new SL-placement and TP-percent input fields remain unknown. Back up the binary diary before upgrading: older EA builds cannot read the new version-2 format. New requests record both inputs as they were at submission. The CSV also derives request spread, original plan risk/reward distance and ratio, signed entry slippage versus the original plan (positive is adverse), and holding seconds for reconciled closes. These price-distance measures are not net monetary R; pending repricing can make original-plan slippage include the effect of a modification. The CSV contains the original score, GT/CT/ST/RG, volume state, style, settings, plan, quote, equity/balance, strategy version and bar provenance, as well as broker IDs, last observed order levels, fill volumes/prices/times, exit reason and deal costs. The binary ledger is authoritative; if CSV export fails, details report it. A lock, corrupt file or failed save disables the ledger visibly without changing trading permissions. Existing quote-observation files remain separate and unchanged in format.

MT records context before sending and binds returned/recovered journal IDs. It validates symbol/magic, broker order history, position identity and deal properties; closure requires no visible position or pending remainder, matching entry/exit volume, and agreement with historical order fill volume. Missing, conflicting or unsupported records stay in REVIEW. FILLED orders are checked against their original volume; canceled, expired or rejected orders require a valid remaining volume to establish any partial fill. Interleaved partial entries/exits are accepted only if cumulative exit volume never exceeds available entry volume at each millisecond; entry and exit deals in the same millisecond are treated as a group. Multiple entry orders and separate non-position charges are not attributed as completed results. Details show the latest unresolved order and reason per lane, and the appended CSV `review_reason` column shows the latest reason for each unresolved row. Reasons are recalculated from current broker history after restart and can change; they are not stored in the binary ledger. An ambiguous request without a recoverable ID, or a crash before context was saved, may remain untracked; existing trades are not reconstructed without their original context. The ledger revisits unresolved records and, for 24 hours, completed or unfilled ones for late broker history/corrections; changes received later are not automatically reflected. The current design stores last confirmed order levels, not a complete timeline of pending modifications. It makes no parameter changes or automatic tuning decisions.

Native compilation and demo testing of fills, partials, cancellation/fill races, manual exits, offline/restart, file locks, server-day rollover and broker-specific fees remain required.

## Phase 4 — broker auto trading

`Auto Trading` defaults to false. When true, and MT5/account permissions permit, MT may submit the existing plan: score ±3 uses a market order unless its closed-bar volume is weak, when it uses a limit; ±2 uses a limit, with the plan lot, one TP and the planned SL only when Stop Loss Placement is enabled. Following SimpleEA's account handling, **new entries require a retail hedging account**; netting/exchange accounts are held. The independent `Allow autotrading M5`, `M15` and `M30` inputs default to true. Each lane requires both its own switch and the master Auto Trading switch to be on. Turning a lane off blocks its new entries and requests cancellation of its pending limits, but retains and continues reconciling any open position. Cancellation can fail or race a fill and is retried while MT is running. The auto row displays its effective ON/OFF state, while the tooltip distinguishes the lane switch from the master. A confirmed cancellation or closure still requires the next close of that timeframe before a replacement. There can be one active order/position per timeframe. After broker records confirm a position has closed or a pending order has ended, any replacement waits for the next close of its own timeframe and uses the new plan. Before a new order, MT checks frozen entry/SL/TP against the live quote and broker stop distance and runs `OrderCheck`; it holds an invalid plan rather than chasing or moving its levels. Market requests use the live Ask/Bid. In normal risk mode MT rechecks the estimated stop loss against current equity and reduces (never increases) the frozen plan lot if needed before sending; the broker-minimum exception still applies. Minimum-lot and bypass-risk modes remain unchanged. The diary records the requested lot alongside the original plan prices. Slippage, gaps and costs can still change actual loss; SL-disabled requests have no protective stop. On a new own-timeframe plan, MT can request a pending entry/SL/TP modification after live-quote, spread, lot/risk and broker checks; broker-confirmed levels remain authoritative. Open positions and their broker-side exits are not modified by this rule. A filled or partly filled order is cleared only when linked entry deals account for the confirmed filled volume and its position is fully closed. Incomplete history, contradictory volume or a missing order ticket stays in REVIEW; an unresolved ticket can require manual investigation. Requests are throttled to at most one attempt per lane every five seconds. New orders require a symbol quote no more than 10 seconds old by the broker-anchored clock. MT also requires broker-reported support for the requested order type, TP and (when enabled) SL, plus a GTC stop-lifetime mode that preserves protective levels across days; symbols without that information are held.


### Stop Loss Placement

`Stop Loss Placement` defaults to `false`. When `false`, newly requested market and limit orders are sent with no broker-side SL, while the planned TP remains required. The plan still calculates and displays an SL, uses it for lot sizing and live-plan validation, and the diary's `plan_sl` remains the planned reference; it is **not** a protective stop. With no broker SL, losses can exceed the planned risk and a position can remain open until TP, manual/broker closure or liquidation. MT does not replace it with a software stop. The auto row explicitly displays `NO SL (unprotected)` when the broker reports none, and the header shows the input state.

Changing an input reinitializes the EA. Existing open positions are never modified by this switch. While disabled, a pre-existing pending order's SL is retained on a replan rather than removed; if keeping it at a new entry would increase planned risk or cannot be verified, MT requests cancellation. A pending order that was placed without an SL stays without one on modification. Re-enabling SL placement requests cancellation of any existing MT pending order lacking SL and marks an open position lacking it for review; it does not silently attach a stop. TP remains mandatory, and partial-fill, spread, broker and other safeguards still apply. Cancellation remains subject to broker confirmation and can race a fill. The legacy observation diary's planned-stop touches do not represent broker exits for SL-free positions.

### Daily trading timer

The optional daily timer has three inputs: `Use daily trading timer` (default `true`), `Timer start` (default `09:15`) and `Timer stop` (default `17:00`). There is no one-time pause input. Times use the **PC/VPS local clock**, not the broker server clock. The start minute is inclusive and the stop minute exclusive; overnight windows such as 22:00–06:00 work. Disable the timer for 24-hour permission; equal start/stop or an invalid time is not a 24-hour schedule. In MT5 Strategy Tester, local time follows the tester's simulated time rather than the host's live wall clock.

With the timer enabled, MT blocks new entries outside the window and requests cancellation of owned pending limits, retrying as existing broker and permission rules allow. Cancellation is not guaranteed: a pending can fill before the broker confirms cancellation. An existing open position is left open with its broker-side SL/TP; the timer never closes or changes it. When the window reopens, each lane waits for its own next closed bar and plan before a new entry. The same fresh-bar wait applies when MT is attached or reinitialized while the enabled window is open. Existing broker-confirmed cancellation/closure cooldowns still apply. When the timer is disabled, existing MT entry behavior is unchanged.

The header shows `Timer: OFF`, `ON`, `PAUSED`, `INVALID` or `CLOCK UNAVAILABLE` beside the trade totals. The complete window or countdown appears below the header when needed and in the badge tooltip; when the market is closed the compact header retains the full timer detail in its tooltip. The auto rows show their effective master-and-lane `ON`/`OFF` state and also show `TIMER PAUSED` when the enabled schedule blocks placement. The countdown is until the schedule opens, not a promise that all other entry rules will pass. A malformed or equal start/stop blocks entries and requests cancellation of pending orders rather than stopping the EA's order management; correct the inputs to resume. Terminal/VPS clock errors affect the schedule. If the terminal/EA is stopped or disconnected, pending cancellations may be delayed and any resting order can still fill. The existing broker reconciliation and fresh-bar rules remain in force.

Run `python3 tests/test_auto_schedule.py` alongside the existing tests. The source-derived stubs exercise schedule boundaries, overnight windows, invalid values, cancellation retries, fill races, open-position retention, restart and independent timeframe bar waits; MetaEditor compilation and MT5/demo-broker behavior remain unverified.

Each M5/M15/M30 auto row shows `Auto: ON` or `Auto: OFF` alongside that lane's confirmed order/position or its current hold/review reason. Hover any part of the row for an explanation. On an empty lane, `no active order` is shown only after broker/journal reconciliation; a qualifying signal can show the current blocker or `Ready: waiting for tick`. Pre-check and definite-rejection codes are retained for that lane's current plan until the next attempt or plan change. Cancellation and modification are requests, not broker confirmation. `REVIEW` means the state cannot be safely established and blocks a new entry, even with Auto OFF displayed. Reasons distinguish missing tickets/history, identity mismatches, incomplete exits and unconfirmed partial fills. If a final historical order omits its position ID, MT uses matching entry deals to find the position, then verifies the order fill volume and that the position’s total entry and exit volume match. It also retries a missing order after explicitly selecting broker history; unavailable or conflicting records remain held. The actual reason for an existing REVIEW depends on the broker's records; MT does not clear missing or ambiguous evidence just because no trade is visible.

MT requests cancellation of an owned pending limit when the lane signal changes direction, becomes NONE or WAIT, the plan becomes unavailable/unsuitable, the target distance does not clear the current spread, or the order lacks a required TP or, when SL placement is enabled, SL. A same-direction upgrade to a valid market plan cancels the limit rather than changing it into a market order; a weak-volume ±3 limit is not a market upgrade. A pending order also expires after three actual completed bars of its own timeframe after broker-confirmed placement; modifying prices does not restart its age. After a pending limit ends, broker reconciliation must complete and any replacement, in either direction, waits for the next close of that timeframe. The same wait applies after a position closes, including at TP or SL. A filled position remains open; it is never replaced while active. When Auto Trading is on and the new plan is otherwise eligible, the auto row shows `Waiting for next closed bar` during this wait. Unknown birth/history is handled conservatively by cancellation, not by resetting the age. Disabling Auto Trading requests cancellation of MT's pending limits and prevents new entries; it does not close an open position. Once a cancellation is requested it stays pending until confirmed by the broker, even if the signal changes again. A partial fill's unfilled remainder is requested for cancellation; the filled position is left open with its broker-side SL/TP. An owned pending order missing TP, or missing SL while SL placement is enabled, is requested for cancellation; an open position missing a required exit is shown as `SL/TP missing: REVIEW` and is not automatically closed or modified. If MT5 or the broker does not permit a cancellation, MT cannot claim it succeeded and will retry while the EA is running. Removing the EA or using an unsupported chart stops its management; it does not itself cancel pending orders or close positions.

When quotes are stale or disconnected, the Bid/Ask badges show `--` rather than cached prices. Plan values and amounts wrap inside their cards when needed.

The auto-execution section appears alongside the trade statistics. They show broker-confirmed positions and limits, not plan or price-touch simulations: direction, OPEN/LIMIT, entry, lot, SL/TP and their estimated gross entry-to-level amounts in USD. A limit's price distance is Ask minus entry for BUY or entry minus Bid for SELL; a negative distance means the level has been passed. On USD accounts, `OrderCalcProfit` is already in USD; otherwise MT searches selected, fresh direct/inverse Forex quotes for conversion and shows `-- USD` if none are available. These estimates do not include fees. The statistics use the separate broker-trade ledger described below.

Auto trading uses per-account/server/symbol shared-file coordination and durable pre-send and pending-modification intents, with a separate tester sandbox. The version-2 journal migrates version-1 records; old pending orders without a verifiable birth bar are requested for cancellation, while confirmed open positions are retained. A modification keeps the broker order volume unchanged; if that volume exceeds the new plan lot (or violates the forced minimum), it is cancelled rather than silently increasing the planned risk. A new modification is not considered effective until the broker shows matching levels; an unconfirmed modification is conservatively cancelled and reconciled. Requests are prechecked with `OrderCheck`; a successful send alone is not a confirmed fill. MT checks broker order/position identities and history before reopening a slot. An ambiguous result, unknown ownership, multiple same-lane objects, unavailable history, a corrupt journal or failed save holds the affected trading instead of blindly repeating. Only the instance holding the lock manages that account/symbol; other instances show the coordinator as unavailable until reinitialized. The lock coordinates terminals sharing the same Common Files on the same machine; it cannot coordinate separate machines. Do not run this EA for the same account and symbol on separate machines without external coordination. The account-mode and protective-level checks apply to new entries; already owned pending orders are still considered for cancellation when disabled.
